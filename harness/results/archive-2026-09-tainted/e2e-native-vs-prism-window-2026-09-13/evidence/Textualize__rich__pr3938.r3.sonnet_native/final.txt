The fix is confirmed working and minimal. Summary:

**Root cause:** In `Console.print`, when `soft_wrap=True` (or `crop=False` generally), rendered segments were pushed to the buffer as-is. Any segment containing a styled `\n` (e.g. a background-colored newline) kept the style code applied around the newline character (`\x1b[...m\n\x1b[0m`), so the reset code came *after* the newline. Terminals apply background color to the new line before processing the trailing reset, causing the color to bleed onto the next line. The `crop=True` path already avoided this via `Segment.split_and_crop_lines`, which strips style from the `\n` segment — but the `soft_wrap` path skipped that logic entirely.

**Fix:** In `rich/console.py` (`Console.print`), for the `crop=False` branch, split any styled segment containing `\n` and emit the newline as its own unstyled `Segment("\n")`, matching the behavior already used in the cropped path.
