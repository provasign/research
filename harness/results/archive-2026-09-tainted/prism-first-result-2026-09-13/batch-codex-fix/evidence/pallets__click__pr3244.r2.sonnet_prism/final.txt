## Summary

The root cause: `CliRunner`'s isolation replaced `sys.stdout`/`sys.stderr` with `io.TextIOWrapper` objects backed by pure `io.BytesIO` streams (`BytesIOCopy`). `io.BytesIO` has no real OS file descriptor, so `.fileno()` raises `io.UnsupportedOperation`, which broke any code passing `sys.stdout`/`sys.stderr` to `subprocess.run` for output redirection (subprocess needs a real fd to `dup2` into the child process).

Fix (`src/click/testing.py`):
- `BytesIOCopy` now also backs itself with a real `tempfile.TemporaryFile()`, exposing a working `fileno()` so `subprocess.run` (and similar fd-based redirection) works under `CliRunner`.
- `write()`/`flush()` mirror to this real file; `getvalue()` reads from the real file (instead of the in-memory buffer) so bytes written directly through the file descriptor by a child process are captured too.
- `close()` releases the backing file descriptor, and `CliRunner.invoke()` explicitly closes the stdout/stderr streams after capturing their contents, avoiding fd leaks/`ResourceWarning`s.
