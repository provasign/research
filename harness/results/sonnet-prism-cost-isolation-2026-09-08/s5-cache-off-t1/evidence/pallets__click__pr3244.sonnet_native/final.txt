## Summary

**Root cause:** `CliRunner.isolation()` captures `stdout`/`stderr` using `BytesIOCopy`, a subclass of `io.BytesIO`. In-memory `BytesIO` objects have no real OS file descriptor, so `.fileno()` raises `io.UnsupportedOperation`. Code under test that passes `sys.stdout`/`sys.stderr` to `subprocess.run(...)` (which needs a real fd) crashes only when run under `CliRunner`.

**Fix** (`src/click/testing.py`):
- Reimplemented `BytesIOCopy` to be backed by a real `tempfile.TemporaryFile()` instead of `io.BytesIO`, while still mirroring every write to the `copy_to` stream. This gives it a genuine `fileno()`, so `subprocess.run(stdout=sys.stderr)` (and similar) now works inside `CliRunner.invoke()`.
- Added `getvalue()` (seek-read-restore) since real files don't have it natively.
- Added `__del__` to close the backing temp file automatically, and close `stream_mixer.stdout`/`stderr` explicitly in `CliRunner.isolation()`'s teardown, avoiding `ResourceWarning`s from unclosed file descriptors.

**Verification:**
- Reproduced the issue's SSCCE (`subprocess.run(["echo", "foo"], stdout=sys.stderr)` inside a `CliRunner.invoke()`'d command) — previously raised `UnsupportedOperation`, now passes.
- Full existing test suite: `1419 passed, 24 skipped, 1 xfailed` (no regressions), including `tests/test_testing.py` and `tests/test_stream_lifecycle.py`.

No tests, docs, or config were modified — only `src/click/testing.py`.
