## Summary

The issue: `CliRunner`'s captured `sys.stdout`/`sys.stderr` were backed by `io.BytesIO`, which has no real file descriptor. Passing them to `subprocess.run(stdout=sys.stderr)` made `subprocess` call `.fileno()`, raising `io.UnsupportedOperation`.

**Fix** in `src/click/testing.py`: changed `BytesIOCopy` (used to back the captured stdout/stderr streams) from subclassing `io.BytesIO` to wrapping a real, OS-backed `tempfile.TemporaryFile()`. This gives it a working `fileno()` (delegated via `__getattr__`), so `subprocess.run(..., stdout=sys.stderr)` works inside `CliRunner.invoke()`, while preserving the existing `write()`/`flush()`/`getvalue()` behavior (mirroring writes into the combined `output` buffer). Added `close()`/`__del__` to release the temp file both explicitly (in `CliRunner.isolation`'s cleanup) and via garbage collection, avoiding `ResourceWarning`s for unclosed OS file descriptors.
