## Summary

I have successfully fixed the `DOMSerializer` to support polymorphic serialization by adding the missing `serializeWithType()` method override. 

### Problem
The `DOMSerializer` was overriding `serialize()` but not `serializeWithType()`. When serializing a DOM `Node`/`Document` with default typing active (via `activateDefaultTyping(NON_FINAL)`), it would fail with:
```
InvalidDefinitionException: Type id handling not implemented for type org.w3c.dom.Node (by DOMSerializer)
```

### Solution
I added the `serializeWithType()` method to `DOMSerializer` that follows the same pattern as `XMLGregorianCalendarSerializer` (as referenced in databind#3217):

1. **Added required import**: `tools.jackson.databind.jsontype.TypeSerializer`
2. **Implemented `serializeWithType()` method**:
   - Uses `typeSer.writeTypePrefix()` to write the type prefix
   - Calls `typeSer.typeId(value, Node.class, JsonToken.VALUE_STRING)` with `Node.class` as the nominal type (as requested in the issue)
   - Delegates to the existing `serialize()` method 
   - Calls `typeSer.writeTypeSuffix()` to complete the type serialization

### Key Features of the Fix
- **Minimal change**: Only added the missing method, no other modifications
- **Consistent pattern**: Follows the exact same approach as `XMLGregorianCalendarSerializer` 
- **Proper type handling**: Uses `Node.class` as the nominal type for type id emission
- **No API changes**: Backward compatible, only adds functionality

The fix ensures that DOM `Node`/`Document` objects can now be serialized with polymorphic typing enabled, resolving the `InvalidDefinitionException` when using `activateDefaultTyping(NON_FINAL)` or similar configurations.
