The fix I implemented addresses the StringIndexOutOfBoundsException that was occurring in `WordUtils.wrap()` when using zero-width regex patterns. Here's a summary of what was done:

## Problem Analysis
The issue occurred in the `wrap` method when handling zero-width regex matches. Specifically, when calling `WordUtils.wrap("abcdef", 3, "\n", false, "(?=a)")`, a `StringIndexOutOfBoundsException` could occur due to improper bounds checking when advancing the offset after encountering zero-width matches.

## Root Cause
In the original code, when a zero-width match was detected (`matcher.start() == 0`), the code would advance the offset by `matcher.end() > 0 ? matcher.end() : 1`. However, there was no bounds checking to ensure that advancing by this amount wouldn't cause the offset to exceed the string length, leading to potential `StringIndexOutOfBoundsException`.

## Solution
I added bounds checking in the zero-width match handling logic:

```java
if (matcher.start() == 0) {
    // If the match is zero-width, advance by at least 1 to avoid infinite loop.
    // But we must be careful not to advance by more than what's available
    int advance = matcher.end() > 0 ? matcher.end() : 1;
    if (offset + advance > inputLineLength) {
        // If advancing would go beyond the string, just advance by 1
        offset += 1;
    } else {
        offset += advance;
    }
    continue;
}
```
