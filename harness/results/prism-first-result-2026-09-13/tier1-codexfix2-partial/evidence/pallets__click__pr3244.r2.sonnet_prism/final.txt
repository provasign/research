## Summary

The `CliRunner` isolation replaced `sys.stdout`/`sys.stderr` with `io.TextIOWrapper` objects backed by plain `io.BytesIO` buffers (`BytesIOCopy`/`StreamMixer` in `src/click/testing.py`). In-memory `BytesIO` has no real file descriptor, so any code invoked under `CliRunner.invoke()` that passed `sys.stdout`/`sys.stderr` to `subprocess.run(...)` (which calls `.fileno()` on non-special stream arguments) raised `io.UnsupportedOperation: fileno`.

**Fix** (`src/click/testing.py`): `BytesIOCopy` is now backed by a real `tempfile.TemporaryFile()` instead of `io.BytesIO`, so `fileno()` (and other file-only operations) work as expected while preserving the class's existing `write`/`flush`/`getvalue`/copy-forwarding behavior via delegation. Added:
- an explicit close of the `StreamMixer` buffers at the end of `CliRunner.isolation()`'s cleanup, and
- a `__del__` on `BytesIOCopy` that closes its backing file, so temp files opened during tests don't trigger `ResourceWarning: unclosed file` if a caller (or test) never closes them explicitly.

Verified:
- The reported reproduction case (`subprocess.run(["echo", "foo"], stdout=sys.stderr)` invoked via `CliRunner`) now passes.
- Full existing test suite: `1419 passed, 24 skipped, 30000 deselected, 1 xfailed` — no regressions, including `tests/test_stream_lifecycle.py` and `tests/test_testing.py`, which exercise `BytesIOCopy`/`StreamMixer` lifecycle directly.

No tests, docs, changelog, or config files were modified — only `src/click/testing.py`. The change was not committed, per instructions.
