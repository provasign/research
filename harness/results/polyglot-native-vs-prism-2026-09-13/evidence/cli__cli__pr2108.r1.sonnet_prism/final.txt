## Summary

The `--web` flag builds a GitHub URL and passes the `-p/--project` value straight through as the `projects` query parameter, but GitHub's web UI expects a project **path** (e.g. `owner/repo/1`) there, not the project **name** used elsewhere in the CLI.

Fix:
- `api/queries_repo.go`: added `ResourcePath` to `RepoProject` (fetched automatically via the existing GraphQL queries) and a new `RepoMetadataResult.ProjectsToPaths` helper to resolve project names to paths.
- `pkg/cmd/pr/shared/params.go`: `WithPrAndIssueQueryParams` now takes the API client/repo, resolves project metadata, and writes resolved paths into the `projects` query param instead of raw names.
- `pkg/cmd/issue/create/create.go` and `pkg/cmd/pr/create/create.go`: updated call sites to pass the client/repo; also fixed the issue-create web condition to trigger query-param building when `-p/--project` is set even without title/body/assignees.

Verified with `go build ./...` (clean) and `go test ./pkg/cmd/pr/... ./pkg/cmd/issue/... ./api/...` — all pass except a pre-existing, unrelated date-formatting test failure in `pkg/cmd/issue/view` that also fails on the unmodified baseline.
