# Prism product proof gate — 2026-09-08

## Decision

The current product passes a narrow change-impact signal but does not establish a
day-to-day coding benefit. Do not claim that Prism improves average coding from
this gate, and do not expand the coding pilot under the staged-spending rule.

The evaluated Prism binary was built from `c805a1101951e03a657170fb92c000254dd64a74`
and had SHA-256
`5738830504e8deaad15d7f4c8333783ff95dd233dd0e5d72d2a2fb53e8d00aba`.
Both strata used Claude Sonnet 5 and GPT-5.5 at medium effort, native versus
Prism, with byte-identical task prompts and normal tool choice. Prism arms used
the product files generated by `prism init --no-permissions`; native arms did
not contain them. There were no quality retries.

## Change-impact cells

Evidence: `runs/product-proof-impact-pilot-2026-09-08`.

Two pinned tasks (Jackson and Grafana), four arms, eight valid cells. Exact
site-oracle scoring produced:

| Treatment | Mean recall | Mean precision | Mean F1 | Total wall time | Total cost | Exact-perfect |
|---|---:|---:|---:|---:|---:|---:|
| Native | 0.8935 | 1.0000 | 0.9359 | 438.750 s | $2.600564 | 1/4 |
| Prism | 0.9958 | 0.9125 | 0.9458 | 345.949 s | $0.868337 | 1/4 |

Prism improved recall and reduced aggregate time and cost. It did not improve
the exact-perfect count. GPT-5.5 Prism over-reported the Jackson task, producing
1.0000 recall but 0.6667 precision. This supports a narrow recall/efficiency
signal, with a real precision defect that must remain visible.

All four Prism cells adopted Prism: Sonnet used MCP and GPT-5.5 used the CLI
fallback. There were no tool errors or protocol violations.

## Day-to-day coding cells

Evidence: `runs/product-proof-coding-pilot-fixed-2026-09-08`.

Two pinned tasks (one local Click bug and one cross-file urllib3 fix), four arms,
and eight Docker-scored patches produced:

| Treatment | Correct fixes | Regressions | Total wall time | Known measured cost |
|---|---:|---:|---:|---:|
| Native | 2/4 | 1 | 802.609 s | $1.969586 across 3/4 cells |
| Prism | 2/4 | 1 | 842.721 s | $2.959625 across 4/4 cells |

All four Click patches passed held-out `FAIL_TO_PASS` and `PASS_TO_PASS` tests.
All four urllib3 patches missed the target fix. Both GPT-5.5 urllib3 patches
also regressed `PASS_TO_PASS`; both Sonnet patches preserved it. Sonnet native
timed out, so its token and cost measurement is incomplete, but its timeout
patch was still scored.

For the fully measured Click pairs, Prism cost $0.646541 versus $0.487049
(+32.7%) and took 334.457 seconds versus 269.848 seconds (+23.9%), with equal
correctness. GPT-5.5 adopted Prism in both coding cells. Sonnet adopted Prism in
neither coding cell even though the MCP server was connected and all six tools
were visible.

This coding gate supplies no correctness or efficiency benefit for current
Prism. Under the predetermined staged protocol, the remaining six coding tasks
should not be run as though the pilot had passed.

## Invalidated predecessor

`runs/product-proof-coding-pilot-2026-09-08` is invalid for comparison. The
dependency install generated `src/urllib3/_version.py` in the native template
after the Prism template had been copied, creating unequal agent environments.
The corrected runner prepares dependencies first, copies that exact tree into
the Prism template, installs Prism second, and aborts if any base file differs.

## What this does and does not prove

This is a product-level pilot gate because it evaluates normal generated Prism
integration, normal model tool choice, paired native controls, exact impact
oracles, held-out Docker coding tests, regressions, total task time, and cost.
It is not a broad average-coding study: the frozen expansion criterion failed
after two coding tasks. It also compares current Prism with native operation;
it does not by itself isolate the causal effect of steering commit `c37a1f4`.
